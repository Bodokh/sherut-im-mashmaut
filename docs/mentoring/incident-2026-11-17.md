# Staff workspace outage, 17 November 2026

Production deployment `6f8bfc9` included management tracking cards, while the production database migration ledger ended at `010_staff_messages.sql`. Both tracking tables from migration `014` were absent. The unconditional tracking read raised PostgreSQL `42P01`, aborting the workspace transaction and returning HTTP 503 for CEO/coordinator accounts. Vercel historical request logs retrieved through Composio contained 17 workspace 503s in the inspected 24-hour window. The same repository read reproduced the missing-relation error against production; mentor reads succeeded.

The hotfix checks table availability before accessing tracking data. An omitted `trackingCards` snapshot property means unavailable; an empty array still means available with no saved cards. Management sees an unavailable notice without tracking edit/report controls. Tracking writes return `not_configured` until both tables exist. Permanent deletion skips tracking cleanup only when both tables are absent and refuses a partial schema before deleting anything.

No migration or production business-data change is part of this hotfix. Migrations `011`–`016` remain a separate rollout: `012` has maintenance requirements, and `016` contains placeholder cleanup. Apply them through the existing ordered, checksum-verified migration process with their documented safeguards. Readiness is checked on each request, so applying the tracking schema requires no feature-flag change or additional deployment.

Regression checks cover absent/partial/ready schemas, unchanged authorization, unavailable tracking writes, deletion safeguards, and unavailable UI versus an available empty card. Production verification must distinguish a successful repository read against the live database from an authenticated browser request to the deployed HTTP endpoint.
